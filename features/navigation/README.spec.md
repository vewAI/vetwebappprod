# Navigation Shell Spec

## User Story

Signed-in users move through VEWAI inside the TailAdmin shell: a collapsible sidebar, a sticky header, and a content column that offsets with the sidebar. Public and full-screen clinical screens stay outside that frame.

## Data Model

```ts
export type ThemeMode = "light" | "dark";

export interface ShellNavItem {
  name: string;
  href: string;
  /** Role gate. Omitted items are visible to every signed-in user. */
  visibleWhen?: "student" | "professor" | "admin";
}

export interface SidebarState {
  isExpanded: boolean;
  isMobileOpen: boolean;
  isHovered: boolean;
  activeItem: string | null;
  openSubmenu: string | null;
}

export interface BreadcrumbItem {
  label: string;
  /** Omitted on the current page. That item renders as text, not a link. */
  href?: string;
}
```

Theme persistence key is `vewai-theme`. When it is unset, the initial mode follows `prefers-color-scheme`. The active mode is the `dark` class on `documentElement`.

## API Contract

No new API routes. The shell reads the current user, role, institution name, and `signOut` from `useAuth()`.

## Component Tree

- `ThemeProvider` — theme state, mounted from `app/layout.tsx`
- `SidebarProvider` — expand, hover, and mobile drawer state
- `AppShell`
  - `AppSidebar` — VEWAI links, VEWAI logos, institution bar, TailAdmin sidebar highlight card
- `SidebarWidget` — bottom-of-nav highlight: title `VewAI`, the communication-skills subtext, and a `Learn More` button to `/`. Hidden while the sidebar is collapsed.
  - `Backdrop` — closes the drawer below the `xl` breakpoint
  - `AppHeader`
    - `ThemeToggleButton`
    - `UserDropdown` — user icon and username centered at the top, then email, role, year group for students, a Dashboard link (`/student` for students, `/professor` for professors and admins), and sign out. The menu sits slightly inset from the window edge.
- `Dropdown` / `DropdownItem` — header menu panel
- `Breadcrumb` — page trail. Items with `href` are links. The last item, without `href`, is the current page.
- `Table`, `TableHeader`, `TableBody`, `TableRow`, `TableCell` — TailAdmin basic table. `TableCell` renders `th` when `isHeader` is true.
- `Select` — TailAdmin select. `options` are `{ value, label }`. `value` and `onChange` are controlled. When the options include `all` or `anytime`, a value other than that idle option is light brand green (the same active-filter look as Created By Me). Form selects without those options stay unhighlighted.
- `FilterSearch` — TailAdmin search input used as a list filter. A non-empty query is light brand green.
- `Alert` — TailAdmin alert. `variant` is `success`, `error`, `warning`, or `info`. Optional `linkHref` / `linkText` render an underline link.
- `Modal` — TailAdmin modal overlay with close control. `WarningAlertModal` is the warning alert confirmation from TailAdmin modals. Form modals use TailAdmin default inputs, labels, and `Select`, with Close and Save Changes in the footer.
- `DefaultTabs` — TailAdmin tab with badge. Underline tabs with no outer card border or padding. Active tab is `text-brand-500` with a `border-brand-500` underline. `items` are `{ id, label, badge? }`. Optional `badge` is a light brand count next to the label. `value` and `onChange` are controlled. Children render below the tab bar.
- `YearGroupRequiredAlert` — warning shown to students with no year group. Link opens `/select-year-group`.
- `SortHeader` + `useTableSort` — clickable table headers. First click sorts ascending; a second click on the same column flips the direction.
- `Pagination` — TailAdmin pagination with text (Previous, page numbers, Next). `page` is 1-based. Hidden when there is only one page.

## Critical Rules

- Main menu, in order: Home `/dashboard`, student Dashboard `/student`, professor Dashboard `/professor` (`professor` or `admin`), Start `/case-sessions`, My Attempts `/attempts`.
- A second menu header, Clinical Cases, follows the main menu and is shown only to professors and admins. It contains Cases `/cases`, Case Sessions `/professor/sessions`, and Students `/professor/students`. Students do not see this header or Available Sessions.
- An Admin menu header follows Clinical Cases and is shown only when `isAdmin` is true. Sub items, in order: Admin Panel `/admin`, Add New Case `/case-entry`, Review and Edit Cases `/case-viewer`, Modify Case Stages `/admin/case-stage-manager`, Nurse Specializations `/admin/nurse-specializations`, Manage Users `/admin/user-management`, Manage Institutions `/admin/institution-management`. LLM Provider Manager and App Specifications Reference stay on the admin page as dialogs and are not sidebar links.
- Dashboard links, including Admin Dashboard, match their path exactly. Every other link is active when the pathname equals `href` or starts with `href + "/"`.
- No shell on `/`, `/login`, `/auth/callback`, `/setup-passkey`, `/case/[id]/attempt`, or `/live/[id]`.
- The shell background (`bg-gray-50`, dark `bg-gray-900`) covers the full page, including content that scrolls past the viewport. The shell does not shrink to the window height.
- Sidebar is expanded by default at `xl` (1280px) and up. Below that it is an off-canvas drawer. Hovering a collapsed desktop sidebar expands it until the pointer leaves.
- Logos are `/images/logo-full.png` (expanded and mobile header) and `/images/logo-v.png` (collapsed). Directly under the sidebar logo, a full-width `bg-brand-700` bar shows the signed-in user's institution name. The bar is omitted when the user has no institution. The bottom of the nav has a TailAdmin highlight card (`VewAI`, communication-skills subtext, `Learn More` to `/`) when the sidebar is expanded, hovered, or open on mobile.
- The header has no search field and no font-size zoom controls.
- `/dashboard` has a greeting card (`Good to see you`) with an info panel for the current academic year dates. Students also see their year group in that panel. Notification cards follow. When there is nothing outstanding, the notification is a TailAdmin Rounded Ribbon card whose ribbon text is `You're all caught up`. `/dashboard`, `/student`, and `/case-sessions` show `YearGroupRequiredAlert` to a student with no year group: they have not selected a year group and must assign themselves to one before they can take any case simulations. The alert link opens `/select-year-group`. Students who already have a year group do not see the alert. `/case-sessions` does not list sessions until a year group is assigned. Nested `/case-sessions/[sessionId]` still redirects unassigned students to `/select-year-group`.
- `/cases` is professor/admin only. It shows `Home` (`/dashboard`) then `Clinical Cases` as the current page. That page has no guided tour. Cases are listed in a basic table (case, species, discipline, difficulty, time). Discipline and species filters use `Select`. Column headers sort the table. Row links open `/case/{id}`. There is no edit-case link.
- `/case/[id]` is the management case dashboard (professor/admin). Breadcrumb is `Home` (`/dashboard`), `Cases` (`/cases`), then the case title. A top card shows the image, title, id, estimated time, and a read-only published checkbox. TailAdmin tabs follow: Case Overview, Sessions (badge = session count), Attempts (badge = attempt count). Overview has a full-width description card, Unique Visitors-style cards for species, category, and difficulty, an Analytics-style attempts chart for the last 30 days, and Top Channels-style cards for sessions and year groups with the most attempts (buttons open the Sessions and Attempts tabs). Sessions lists every session for the case (create session in the tab), with year-group (`All Year Groups`), academic year (`Current Academic Year` or `Anytime`, default current), and status filters. Current academic year keeps sessions that start after the signed-in user's institution academic-year cutoff (31 July if unset). Attempts lists every attempt, with year-group (`All Year Groups`), academic year (`Current Academic Year` or `Anytime`, default current), and status filters, plus student search. The Year column is the session's year group, not the student's current year. Current academic year keeps attempts after that same cutoff. Session links go to `/professor/sessions/{sessionId}`. Attempt rows open `/attempts/{id}?from=case`. Students hitting this URL are sent to `/case/{id}/instructions`. There are no instructions on this page.
- `/case/[id]/instructions` is the start/participate case page. Breadcrumb is `Home` (`/dashboard`), `Start` (`/case-sessions`), then the case title. It shows case details, instructions, the current user's latest 3 attempts, and active or scheduled sessions. Attempt rows link to `/attempts/{id}?from=case`. Session rows link to `/case-sessions/{sessionId}`. If there are more than 3 own attempts, a link opens `/attempts?caseId=` for that case. Sessions are a table (session, status, starts, ends) with no Start Case button.
- `/case-sessions` shows `Home` (`/dashboard`) then `Start` as the current page. There is no back-to-home link. With `?caseId=` the breadcrumb is `Home`, `Start` (`/case-sessions`), then the case title, and a View case control opens `/case/{id}/instructions`. Session cards open `/case-sessions/[sessionId]`. Students only see sessions for their current year. Unassigned students see `YearGroupRequiredAlert` and no session list. Nested `/case-sessions/` routes still send unassigned students to `/select-year-group`.
- `/case-sessions/[sessionId]` shows `Home` (`/dashboard`), `Start` (`/case-sessions`), then the session friendly name. It is the student session page: Start card with year group, window, and countdown, case card (View Case opens `/case/{id}/instructions`), and the current user's attempts (View opens `/attempts/{id}?from=session`). It does not show professor analytics.
- `/attempts` shows `Home` (`/dashboard`) then `My Attempts` as the current page. Attempts are listed in a basic table (case, year, status, difficulty, date, time). The Year column is the session's year group, not the student's current year. Every row links to `/attempts/{id}` regardless of status. Filters are year group (the session's year group, All Year Groups plus Unassigned), case, status, and academic year (`Current Academic Year` or `Anytime`, default current). Current academic year keeps attempts after the institution academic-year cutoff (31 July if unset). `?caseId=` preselects the case filter. There is no search field. Column headers sort the table. Default order is newest first.
- `/attempts/[id]` breadcrumb follows `?from=`. `from=session` is `Home` (`/dashboard`), `Case Sessions` (`/professor/sessions`) for staff or `Start` (`/case-sessions`) for students, the session name (`/professor/sessions/{sessionId}` or `/case-sessions/{sessionId}`), then the attempt title. `from=case` is `Home`, `Cases` (`/cases`) for staff or `Start` (`/case-sessions`) for students, the case title (`/case/{id}` for staff, `/case/{id}/instructions` for students), then the attempt title. `from=student` (staff) is `Home`, `Students` (`/professor/students`), the student email (`/professor/students/{userId}`), then the attempt title. Missing or other `from` is `Home`, `My Attempts` (`/attempts`), then the attempt title. There is no back-to-attempts link. Three cards sit in a row: Attempt Details (student, status, started, completed, time spent; for professors and admins the student email links to `/professor/students/{userId}` and Delete Attempt is an outline button at the bottom), Session Details (name, status, start, end, professor; session-ended warning lives here; View Session opens `/professor/sessions/{sessionId}` for staff and `/case-sessions/{sessionId}` for students), and the case card. There are no separate student, professor, started, completed, or time-spent cards. Two TailAdmin tabs with badge follow inside a card: Conversation then Feedback. The Feedback tab badge is the unread feedback count, and is omitted when there is none. If the attempt is in progress, belongs to the signed-in user, and either has no session or the session has not ended, a Continue Attempt button appears above the cards and opens `/case/{caseId}/attempt?attempt={id}`. If the attempt is in progress and its session has ended, the Session Details card says the attempt cannot be completed because the session has ended.
- `/student` is the student dashboard. It does not redirect to `/` or `/dashboard`. Unassigned students see `YearGroupRequiredAlert`. Breadcrumb is `Home` (`/dashboard`) then `Dashboard` as the current page. It shows a profile card (user icon, email, created date, assigned year group), a Start button with icon that opens `/case-sessions`, attempts per month for the last 12 months, and the latest 3 in-progress attempts with a View link to `/attempts/{id}`.
- `/select-year-group` is for students with no year group. It lists that institution's year groups and the academic year-end date. Students who already have a year are sent to `/student`. Professors and admins are sent to `/dashboard`.
- `/professor` shows `Home` (`/dashboard`) then `Dashboard` as the current page. It shows TailAdmin Card with Icon metric cards for Total Cases, Total Active Sessions, and Total Students Enrolled (icon left of title and count; View all opens `/cases`, `/professor/sessions`, and `/professor/students`), an Analytics-style Attempts Per Day chart (subtitle Last 30 days), Top Cases and Recent Sessions (Top Channels cards), and Students by year group (Sessions By Device donut). Top Cases has a Last 30 days subtitle; case names link to `/case/{id}` and the button opens `/cases`. Recent Sessions has a Created by you subtitle, lists the current user's newest sessions, session names link to `/professor/sessions/{id}`, and the button opens `/case-sessions`. The action buttons on those two cards sit at the bottom of the card.
- `/professor/students` is professor/admin only. Breadcrumb is `Home` (`/dashboard`) then `Students` as the current page. The page title is `Students`. Students (role student or null) are listed in a basic table (email, year, joined). Search filters by email (debounced) and is applied on the server. Year filter uses `Select` and defaults to All Year Groups, including Unassigned. Active filters use the shared light brand-green control. Email and Joined sort on the server. Year is not sortable. Default order is email A–Z. The list is server-paged (25 per page) with TailAdmin pagination under the table. A result count is top right above the table. Row links open `/professor/students/{userId}`. Professors only see students in their institution. There is no last-sign-in column.
- `/professor/students/[id]` is professor/admin only. Breadcrumb is `Home` (`/dashboard`), `Students` (`/professor/students`), then the student email. It shows a profile card (user icon, email, joined date, last sign in, year group), an Analytics-style Attempts Per Month chart for the last 12 months, and an Attempts card with the student's attempts table (case, session, year, status, date, time). Filters are year group (the session's year group, All Year Groups plus Unassigned), case, status, and academic year (`Current Academic Year` or `Anytime`, default current). Current academic year keeps attempts after the institution academic-year cutoff (31 July if unset). Attempt rows open `/attempts/{id}?from=student`. Session names open `/professor/sessions/{sessionId}`.
- `/professor/sessions` shows `Home` (`/dashboard`) then `Case Sessions` as the current page. Sessions are listed in a basic table (session, case, year, status, starts, ends). Filters are creator (`Created By Me` or `Created By Everyone`, default `Created By Me`, first in the row, brand green), status, case, and year group (default All Year Groups). A result count is top right above the table. `?caseId=` preselects the case filter. There is no search field and no dashboard button. Column headers sort the table. Default order is latest start first. Sessions with no year show `—` in the year column and stay visible to staff.
- `/professor/sessions/new` shows `Home` (`/dashboard`), `Case Sessions` (`/professor/sessions`), then `Create Session` as the current page. The page title is `Create Session`. There is no back-to-sessions link.
- `/professor/sessions/[sessionId]` shows `Home` (`/dashboard`), `Case Sessions` (`/professor/sessions`), then the session friendly name as the current page. There is no back-to-all-sessions link. Two TailAdmin tabs with badge: Session Information (session including year group, case, AI group report, attempts-per-day and attempt-status charts) then Attempts with a badge for the attempt count (email column, search by email, status filter, result count top right, standard attempts table). Attempt rows open `/attempts/{id}?from=session`.
- `/case-viewer` is admin-only. With no `id` it matches `/cases` (filters, table) except the page title is `Review and Edit Cases`, the subtitle is `Select a case to edit`, row links open `/case-viewer?id={caseId}`, unpublished cases are listed, and there is a Published column. Breadcrumb is `Home` (`/dashboard`), `Admin` (`/admin`), then `Review and Edit Cases` as the current page. With `?id=` it shows `Home` (`/dashboard`), `Admin` (`/admin`), `Review and Edit Cases` (`/case-viewer`), then the case id as the current page. That editor is full width, loads a single case, and does not browse previous/next cases. The page title is the case title and the subtitle is the case id. Publish and Unpublish buttons sit with Edit and Archive. A TailAdmin warning alert modal confirms either action. The Published column uses a tick or a cross. The save control is shown only while editing. There is no show-archived control. The case image is at most 300px wide.
- `/admin` is admin-only. Breadcrumb is `Home` (`/dashboard`) then `Admin Panel` as the current page. The page title is `Admin Panel`. There is no help icon and no guided tour. Options are shown as cards, three per row, each with a title and short description.
- `/case-entry` shows `Home` (`/dashboard`), `Admin` (`/admin`), then `Add New Case` as the current page. The page title is `Add New Case`.
- `/admin/user-management` is admin-only. Breadcrumb is `Home` (`/dashboard`), `Admin` (`/admin`), then `User Management` as the current page. The page title is `User Management` with no help icon and no guided tour. Create User is in the top right. Users are listed in a basic table (email, role, institution, year, created, actions). Search filters by email. Role and year filters use `Select`. Year defaults to All Year Groups and includes Unassigned. Column headers sort the table. There is no student-to-professor assignment UI. Create and edit use a TailAdmin form modal (two-column fields, Close and Save Changes). The year-group select is filtered by the user's institution; admins can assign or clear it for students.
- `/admin/institution-management` is admin-only. Breadcrumb is `Home` (`/dashboard`), `Admin` (`/admin`), then `Institution Management` as the current page. The page title is `Institution Management`. Create Institution is in the top right on the list view. Institutions are listed in a basic table (name, created, actions). Column headers sort the table. Manage Institution includes academic year end (day + month, default 31 July) and year-group create/delete, next to Domains and Default roles.
- `/admin/nurse-specializations` is admin-only. Breadcrumb is `Home` (`/dashboard`), `Admin` (`/admin`), then `Nurse Specializations` as the current page. The page title is `Nurse Specializations`. Add Species is in the top right.
- Radix dialog, popover, select, and tooltip overlays sit above the sticky header.
